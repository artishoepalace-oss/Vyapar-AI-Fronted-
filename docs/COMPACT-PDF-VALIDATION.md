# Compact UI and local invoice PDF fixes — 9 September 2026

## Source and release

The starting project is the uploaded UI-organized source, reconciled with the current 00005 frontend/native source at GitHub commit `66a1d1aa487989f79b5cbce31cecca561c50dcd4`. This ZIP is a local fix release, **20.10.2004.00006.2026 / 2010200406**. It has not been pushed or published.

## What changed

Business sections are nested inside `#businessToolResults`. The prior category organiser looked only at immediate shell children, so it missed them and displayed every category. It now finds nested sections. Search and category visibility share the selected tab, including screen-reader visibility. Two tool columns fit typical phone widths; below 340px the layout falls back to one column. Primary actions retain at least 44px height. The unused module placeholder stays hidden until a tool opens.

The logo tile remains centred. Its existing bitmap moves up by 12% inside a fixed white frame; measured against the shop body rather than the decorative star, this targets roughly two parts space above and three below. No bitmap was redrawn. The sign-in, header, native loading cover and HTML loading cover share the adjustment. Native Android launcher icons remain the original asset.

The small permission introduction is shown once per app storage after sign-in. Dismissing it does not trigger native permission requests. Android owns the subsequent OS dialog. The existing camera/printer integrations remain feature-triggered. Android 10+ saves its own MediaStore downloads without broad storage permission; Android 7–9 can request legacy storage permission on download.

`invoice-pdf.js` isolates PDF generation and save coordination. Its local PDF-Lib dependency is loaded lazily and requires no CDN or server round trip. It exports saved transaction values without modifying accounting data. New platform invoices store discount as a percentage; old bills have an explicit `discountAmount`. Both schemas are handled, along with saved tax breakdown, additional charges, payments and balance. Very long rows wrap over pages with repeated invoice/table headers. Thermal PDFs use full-width item descriptions followed by quantity/rate and amount.

The Android bridge decodes and writes on the background executor, removes incomplete MediaStore records on failure, avoids overwriting older exports, and sends a result only after the save finishes. Permission denial and errors are surfaced honestly. The browser fallback starts a Blob download; it cannot verify that the user kept the file. The existing Print and ESC/POS actions remain available separately.

## Remaining device verification

No APK was built and no physical device or Android emulator was available. The local preview was unavailable to the cloud browser, so browser screenshots and frame timing could not be obtained. Test the following on a real Android device before distributing an APK:

1. Open Business at 360–430px logical widths. Switch all four categories, search for an invoice tool, clear, open a tool and return. Confirm readable labels, no horizontal page overflow and comfortable touch targets.
2. Fresh app storage: sign in, view the short introduction, choose Not now, relaunch. It must not repeat. On Android 13+, repeat with Continue to check the OS notification dialog.
3. Save an A4 invoice with 75+ lines, then A5 and 58/80mm variants. Confirm the PDF exists under Downloads/Vyapar AI, opens locally and reports the right final totals. Save twice to confirm unique names.
4. On Android 7–9, deny the storage prompt and retry with permission granted. Check that denial is not reported as success. Check failure messaging when storage is full.
5. Inspect the logo through launch → sign-in → header. Check keyboard opening, repeated navigation and reduced-motion behavior on the target device.
6. Export Hindi/other Unicode business and item names. Latin text stays selectable vector text; Unicode uses device canvas font shaping and is embedded as high-resolution images, so it is not searchable text. The device font path has not been visually verified here. Data-URI PNG/JPEG business logos are supported; remote logo URLs are not fetched during offline export.

Live login services, Google Drive, payments and Bluetooth printing were not exercised.
